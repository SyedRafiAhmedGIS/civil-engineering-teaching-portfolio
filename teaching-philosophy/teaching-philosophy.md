## Engineers learn by building, testing and defending

Civil engineering should be taught the way engineers actually work: from problems whose
answers must survive evidence. In the concrete technology and surveying courses documented
here, students measure,
compute, compare against a standard and then defend their result - in a report, a rubric-
marked defence, or a five-minute presentation. The teaching portfolio repository that
accompanies this statement is itself built on that principle: the syllabi, the lab manual
and the grading rubric are not documents about teaching, they are the instruments of it,
and the included Python toolkit with its passing test suite shows the standard of
reproducibility the course asks of students.

## Three commitments behind every course

**1. Outcomes first, and visibly so.** Each course in this portfolio carries a published
outcomes-to-assessment map - every assessment is traceable to a declared outcome, and
students see that map on day one. When an outcome's class average falls below threshold,
the plan is to change the paired activity the following term and record the change in the
course file. The loop matters
more than the paperwork: assessment exists to improve teaching, not to ration grades.

**2. Authentic tasks over abstract drills.** The slump test is designed to be taught with a
live demonstration and a data sheet each student completes and signs; the traverse closes
only if the error model was applied correctly; the GIS project must use open data with
stated sources. These
are small authenticities, but they change how students behave - they check, they label,
they justify. The included grading rubric rewards exactly that behaviour, which is why
analysis and methodology outweigh presentation in its weights.

**3. Honest technology in honest hands.** Computation belongs in every course - not as
decoration, but as the quality-control tool the profession uses. The country-specific
notebook suite (US, UK, India, Bangladesh standards) lets a student in any jurisdiction run
the same laboratory analysis under their own national rules, with an optional upload widget
for real class data. Students see version control, tests and reproducible figures - and
every tool they are handed also carries a marked limitations section, because knowing
what a calculation does *not* prove is a core engineering skill.

## The classroom I aim to run

Inclusive by design: every demonstration has a remote equivalent (the notebooks run with
built-in synthetic data when a student cannot attend), every rubric is published before the
work, and every unfinished item in these materials is labelled as planned rather than
improvised. I would rather hand a committee a repository that says *here is what is done,
here is what is next* than a polished facade - the same honesty expected of students when
their data does not close.

## Where I am going

Next steps in my teaching development: expanding this repository's lecture library to a
complete slide deck set for each course (planned on the repository roadmap), building an auto-graded quiz
bank keyed to the outcome maps, and developing a field-data collection template so surveying
notebooks feed directly into GIS labs - turning three courses into one coherent,
data-driven first- and second-year sequence.
